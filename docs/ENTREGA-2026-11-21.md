## Compatibilidade e decisão de publicação

Entre a main `bc5d582` e a candidata, o SQL, o inicializador do App Service, o preparador do banco e a versão de Better Auth permanecem iguais. No modo e-mail o startup adquire advisory lock, executa o SQL com CREATE TABLE IF NOT EXISTS e verifica/aplica migrações de autenticação antes de iniciar o Next.js. A identidade precisa das permissões existentes e o pool precisa permitir uma conexão adicional. CREATE TABLE IF NOT EXISTS não corrige uma tabela preexistente com coluna ausente. O PR acrescenta campos opcionais às transações no JSON e preserva registros sem natureza. A revisão de código e o PostgreSQL de teste sustentam a compatibilidade esperada. A versão instalada e eventuais desvios de esquema no Chile precisam de conferência por Gabriel.

Verifica em cópia isolada tabelas de autenticação, colunas de workspaces e rate_limits, reaplicação do startup, login e saldos de registros legados. Mantém configurações e credenciais em armazenamento privado.
2. Antes de integrar, conferir o diff efetivo de todos os workflows, execuções de deploy em fila ou em curso e qualquer integração de publicação no Deployment Center. A main atual publica em push. Um push intermediário, integração parcial ou resolução de conflito que preserve a condição antiga pode publicar. O merge completo com o YAML revisado executa CI em push e exige workflow_dispatch na main com deploy_to_production=true para upload e deploy. O sinalizador inicia desmarcado. 3. Somente após autorização de integração e CI verde no SHA exato, Gabriel confere o YAML já na main, o Node 24 x64, o comando npm start, TLS, a configuração privada existente e o pacote de retorno. Com autorização separada para publicar, dispara o workflow manual nesse SHA da main e registra o hash do ZIP gerado nessa execução. O job aponta diretamente para Production.
4. Se falhar inicialização, isolamento, persistência ou leitura dentro dos limites do plano, interromper o uso e, com autorização, republicar o pacote anterior identificado. Antes de reabrir escrita, conferir registros novos: o código antigo pode ignorar natureza, tratar transferências como consumo ou descartar campos novos durante edição. Preservar as gravações posteriores ao backup. Restauração de banco requer decisão específica e ensaio isolado. [Procedimento de backup e rollback](DEPLOYMENT.md)
